ATLAS

The agent that sees your screen, understands your intent, and takes action.

A full-stack AI agent that operates real software the way a person does: across desktop apps, browsers, and mobile, using only what appears on screen.

The system

Five components, one agent

ATLAS is a full stack: perception and reasoning at the core, with a desktop launcher, a relay backend, and a mobile companion wrapped around it.

  • ml/

    ML Pipeline

    A vision-driven desktop agent that operates any app using only screen pixels. It runs a perceive, understand, plan, act, verify loop with local models: Ollama (llama3.2 and llava) and EasyOCR.

  • ml/mcp/

    MCP Browser Agent

    Autonomous web automation through Playwright MCP and an LLM action loop, driving a real Chrome browser to complete tasks on live sites.

  • backend/

    Backend

    A FastAPI WebSocket relay that bridges the mobile app to the agent, orchestrating commands and streaming progress back in real time.

  • frontend/

    Frontend

    A Tauri v2 and Next.js desktop launcher, Spotlight style, that indexes and opens local files and apps. Toggle it any time with Win and minus.

  • companion-app/

    Companion App

    A Flutter mobile client to send voice or text commands and watch progress live as the agent works on your machine.

  • the idea

    One intent, end to end

    Speak or type a goal on your phone. ATLAS perceives your screen, decides what to do, acts with mouse and keyboard, and verifies the result, then reports back.

How it works

The perception loop

Every action follows the same disciplined cycle. The agent never assumes: it looks, reasons, acts, and then checks the screen again before moving on.

  1. 01

    Perceive

    Capture the screen and read it with OCR to locate text, controls, and layout.

  2. 02

    Understand

    Interpret what is on screen and how it relates to the current goal.

  3. 03

    Plan

    Decide the next single action that moves the task forward.

  4. 04

    Act

    Execute it with real mouse and keyboard input, never hardcoded coordinates.

  5. 05

    Verify

    Look again to confirm the action worked, then loop or recover.

The loop repeats until the goal is reached or the agent needs help.

Design principles

Rules the agent lives by

  • *

    The screen is the only truth

    ATLAS reads real pixels, not an app's internal state, so it works with software it has never seen.

  • *

    Never trust one perception pass

    Perception can be wrong. The agent corroborates before committing to an action.

  • *

    Always verify visually

    After acting, it looks again to confirm the outcome instead of assuming success.

  • *

    Never hardcode coordinates

    Targets are found on screen every time, so the agent adapts to any layout or resolution.
